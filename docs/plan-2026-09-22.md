# Frequencies — a private, decentralized, uncensorable event-organization app

**Frequencies** is a production tool for the music / club-night scene — booking nights, artists, crew, gear, budgets, promo — built the way we build everything: **local-first, end-to-end private, and impossible to deplatform.** It runs on the Logos Network and is assembled from **reusable Basecamp modules**, so the scene owns its data and no platform can surveil it, sell it, or switch it off.

> The thesis: the tools underground scenes rely on today (Google Calendar, Resident Advisor, group chats, spreadsheets, ticketing platforms) are centralized — they can deplatform an organiser, leak a guest list, go down the week of a festival, or hand data to whoever asks. A scene's coordination shouldn't have a kill switch. Frequencies puts the calendar, contacts, money, files and comms **on the members' own devices**, synced peer-to-peer over Logos, readable by no one else.

---

## Principles

- **Private by construction.** Every calendar/room/ledger is sealed with a key only its members hold (zero-trust household model); the network moves ciphertext it can't read.
- **Decentralized & uncensorable.** No server owns the data or the namespace. Sync rides Waku; there is nothing to seize, subpoena, or take offline.
- **Local-first & offline-first.** Everything works on a plane, in a basement venue with no signal, at a border. State lives on-device; peers converge when they reconnect (append-only CRDT, last-write-wins + tombstones, no lost edits).
- **Own your identity.** Members sign with their own keys — software or a hardware Keycard (a person, not an account) — so authorship and permissions are cryptographic, not granted by a platform.
- **Reusable modules, one app.** Each capability is a standalone **Basecamp module** (desktop + Android) that any Logos app can adopt. **Frequencies** is the orchestration layer that composes them into one product and UX. Nothing is single-use.
- **Logos-native.** Lean on Logos Network infra wherever it exists rather than rebuilding it.

## Lean on Logos Network infra

| Need | Logos infra we use |
|---|---|
| Peer-to-peer messaging / sync | **Waku** (via `loam-transport` — one shared node for all modules) |
| File storage (posters, riders, contracts, logos) | **Codex / Logos Storage** — content-addressed, encrypted, no S3 |
| App platform (desktop) + distribution | **Basecamp** modules + our F-Droid/Basecamp repos |
| Identity & signing (per person, hardware-optional) | **Logos identity + Keycard** (`loam-keycard`) |
| Convergence engine (CRDT/HLC/reconciliation) | **`loam-sync`** (shared "sync brain") |

## Architecture — a stack, not a monolith

```
┌───────────────────────────── Frequencies (the app) ─────────────────────────────┐
│  Domain glue: an *event* links → its artists · crew · budget · tasks · gear      │
│  Venue-specific UX · external integrations (tickets, weather, maps)              │
├──────────────────────────── Reusable Basecamp modules ──────────────────────────┤
│  scala (calendar) │ kym (money) │ kith (contacts) │ qaku (Q&A) │  NEW: crew ·    │
│                   │             │                 │            │  gear · tasks   │
├───────────────────────────── Loam substrate (shared) ───────────────────────────┤
│  loam-transport (Waku node) · loam-sync (CRDT) · loam-keycard (identity)         │
├────────────────────────────── Logos Network infra ──────────────────────────────┤
│  Waku (messaging) · Codex/Logos Storage (files) · Basecamp (platform)            │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Each middle-row box is an independent module with its own sync, permissions and mobile app; **Frequencies** is the top row — it composes them and adds the domain links + UI. **Scala** is one module, but given the nature of the product (everything hangs off *when* and *where*), likely the spine.

**The shared substrate**
- [loam-transport](https://github.com/vpavlin/loam-transport) — the shared Waku/Logos delivery node
- [loam-sync](https://github.com/vpavlin/loam-sync) — event-log CRDT + HLC + RBSR catch-up
- [loam-keycard](https://github.com/vpavlin/loam-keycard) — hardware/per-person identity + signing
- [loam](https://github.com/vpavlin/loam) — the Loam node app

**Existing domain modules to reuse**
- [scala](https://github.com/vpavlin/scala) — the calendar (this protocol) · [kym](https://github.com/vpavlin/kym) — budgets · [kith](https://github.com/vpavlin/kith) — contacts · [qaku](https://github.com/vpavlin/qaku) — Q&A · [perun](https://github.com/vpavlin/perun) — reference core+view split

## Requirements → where each lives

**The rule:** *Is it "an event on a shared timeline" (fields, files, recurrence, reminders, permissions)?* → **Scala.** *A different domain entity (a person, gear, money, a task) or an external integration?* → **the app**, as its own module on the same substrate.

### ① Lives in **Scala** (already, or a natural extension)

| Requirement | Status |
|---|---|
| Shared calendar + per-member permissions | ✅ owner / editor / viewer + Closed/Open/Collaborative |
| Recurring events (residencies, club nights) | ✅ `recur` |
| Notes per event | ✅ description + custom fields |
| Files attached (posters, riders, contracts) | ✅ attachments via Logos Storage |
| Public/private toggle | ✅-ish (open/collab tiers; a "community-public" tier is a small extension) |
| Colour coding · Draft/Confirmed/Cancelled badges · Tags · event-type | ✅ mechanism — **custom schema fields** (`enum` + `color` field types); view renders badges, app defines values |
| Reminders | ✅ `getPendingReminders` |
| Poster/image preview in the grid | 🔶 extend — view renders image attachments inline |
| Search & filter over events | 🔶 extend — event query/filter API |
| Month / **week** / **timeline** views | 🔶 extend — month exists; add week + timeline |
| Drag & drop to move events | 🔶 extend — it's editing start/end, which Scala already does |
| Duplicate an event in one click | 🔶 extend — trivial clone |
| Internal comments/chat per event | 🔶 Scala (comment events) or a shared "threads" module — **not** the app |
| Conflict warnings (time overlap) | 🔶 partial — Scala gives the *time-overlap* primitive; "same **artist**/crew" needs the domain model |

### ② Sibling modules on the same substrate — reuse what exists

| Requirement | Where |
|---|---|
| Budget tracker (expenses, income, profit) | → [**kym**](https://github.com/vpavlin/kym) |
| Artist database / contacts (+ fees) | → [**kith**](https://github.com/vpavlin/kith) (add a `fee` field) |
| Community Q&A / knowledge base | → [**qaku**](https://github.com/vpavlin/qaku) |
| Crew roster + assignments + "I'm here" check-in | → **new module** (people + assignments; check-in is an event) |
| Equipment inventory + per-event checklist | → **new module** (gear catalog + per-event checklist) |
| Task lists + deadlines + reminders | → **new module** (tasks); deadlines are Scala events, reminders are Scala's |
| Availability calendar (lettuce-meet style) | → **new module** (availability polling) |
| Social media planner | → a **Scala calendar of "post" events** + a thin domain module |

### ③ Higher-level app only (domain glue, UI, integrations)

| Requirement | Why app-level |
|---|---|
| Ticket-sales integration | external API (the paste-link/number can be Scala fields) |
| Weather forecast · Map view of venues | external APIs + venue entities |
| Analytics (events/month, attendance, revenue) | aggregates *across* Scala + KYM + crew data |
| Push notifications | delivery is platform/infra; the *trigger* (reminders) is Scala's |
| Dark mode · Mobile-friendly quick editing | cross-cutting theming; you get mobile free (extend Scala's app) |
| Conflict "same artist booked twice" | domain rule over ①'s overlap primitive + ②'s artist/crew data |

## What we reuse vs. build

| Reuse today | Extend | Build new |
|---|---|---|
| scala · kym · kith · qaku · loam-transport · loam-sync · loam-keycard · Logos Storage | scala: week/timeline views, drag-drop, search API, per-event comments, image preview, "community-public" tier; kith: `fee` field | crew · equipment · tasks modules; Frequencies domain-glue + UI; external integrations (tickets/weather/maps) |

## Suggested build order

1. **Harden Scala as the spine** — the calendar is where 60% of the essentials already live; add the small view extensions (week/timeline, drag-drop, search, image preview).
2. **Wire in the modules we have** — kym (money) and kith (artists/contacts) via the shared substrate, linked to events by id.
3. **Add the missing domain modules** — crew, equipment, tasks (each a proper Basecamp module + mobile, reusable beyond Frequencies).
4. **Frequencies domain layer** — the links (event ↔ artist/crew/budget/tasks/gear), the conflict rules, the unified UX, then the external integrations.

Everything above ships as a reusable Basecamp module (desktop + Android) on the Logos Network — Frequencies is the concert they play in.
